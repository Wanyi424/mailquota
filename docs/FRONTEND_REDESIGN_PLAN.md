# MailQuota 管理端重构方案

## 目标

管理端围绕一条清晰的工作闭环组织：管理员创建客户，保存一次性密钥，启用客户，配置邮件内容，再处理发送结果不明确的记录。每个步骤都要告诉管理员当前状态、下一步动作和操作结果。

本次重构保留现有管理 API、会话安全边界和数据模型，不引入图表大屏、多角色权限或客户自助端。桌面端承担高密度管理工作，手机端保证表单、关键操作和记录处理可用。

## 现状根因

- 登录后固定进入客户列表，直接打开深层链接时会丢失原目标和筛选条件。
- 客户和记录列表把数据全部拉到浏览器后再筛选分页，规模增长后首屏和刷新都会变慢，也违背默认分页约束。
- 创建、记录详情和人工结算依赖组件内弹窗状态，无法分享、刷新恢复或使用浏览器后退回到原上下文。
- 刷新和网络错误会卸载标题、筛选器和已有结果；管理员无法保留上下文后重试。
- 未保存拦截只覆盖应用内链接，浏览器后退和前进仍可能丢失模板修改。
- 详情页的客户、配置和记录之间没有共享工作上下文，切换栏目会重复读取数据。

## 目标信息架构

```text
/login?next=...
  └─ /overview                         工作台首页
      ├─ /customers                    客户列表
      ├─ /customers/new                创建客户与接入清单
      ├─ /customers/:id                客户概览
      ├─ /customers/:id/settings       发件身份、额度、启停和密钥
      ├─ /customers/:id/template       邮件模板
      ├─ /customers/:id/records        当前客户记录
      └─ /records?status=unknown       全部发送记录与待确认队列
          └─ /records/:id              可分享的记录详情与处理入口
```

第一阶段先落地 `/overview`、登录回跳、稳定的应用壳、客户列表和客户详情主链路。受现有 API 边界限制，工作台的客户与额度数据标明当前展示范围，待确认数量保持精确；全局聚合、模板与记录的深层迁移放到后续契约阶段。现有模板与记录 URL 保留兼容，后续逐步迁移到嵌套路由和可深链抽屉。

## 页面与交互原则

### 工作台首页

首页只回答三个问题：有多少客户、哪些客户额度有风险、有没有需要人工确认的发送记录。待确认数量是主行动入口，点击后进入保留筛选条件的记录队列；低额度客户直接进入对应详情。

### 客户列表

列表使用现有接口分页，默认每页 20 条，最多 100 条。当前页筛选只用于缩小已加载的 20 行，避免把现有接口伪装成全库搜索；全库搜索放到后续接口契约阶段。页码写入 URL，刷新和返回可以恢复。工具条保留在加载和错误状态，数据区域显示局部骨架或错误重试，不清空管理员当前上下文。

### 客户详情

详情页固定显示客户身份、启用状态和可用额度。概览、设置、模板、记录是同一工作区的栏目，切换栏目保留客户上下文。高风险操作说明实际影响并二次确认；普通保存给出局部保存状态。

### 记录与待确认

记录详情使用路由状态而不是组件私有弹窗状态。处理完成后保留原筛选和分页，明确显示处理结果与剩余待确认数量；遇到状态冲突时刷新当前记录并解释“已被其他页面处理”。

### 创建与密钥

创建客户后进入接入清单：服务地址、客户 ID、一次性密钥、复制状态和“进入客户详情”动作集中呈现。密钥仍只显示一次，关闭前不能误触关闭。

## 视觉与动效

采用安静的运营工作台：低饱和紫色作为品牌和主行动色，绿色、琥珀色、红色只表示明确业务状态；减少无信息装饰，操作按钮紧邻对象。布局使用稳定的内容宽度、8px 间距节奏和清晰的表格层级。

交互反馈优先使用局部状态：保存按钮显示进行中和已保存，数据刷新保留旧内容并叠加轻量状态，抽屉和页面切换使用 150–200ms 的进入过渡。所有动效遵守 `prefers-reduced-motion`。

## 分阶段交付

### 第一阶段：工作台主链路

- `/overview`、登录 `next` 回跳和 404 返回链路。
- 新的应用壳、顶栏、导航和响应式基础 token。
- 客户列表保留现有 API，改为真实分页、页码 URL 状态和局部加载/错误反馈；全局搜索不在现有契约上做假实现。
- 客户详情主链路的稳定头部、栏目导航和返回路径。
- 桌面端与手机端的核心布局、键盘焦点和基础无障碍修复。

### 第二阶段：配置工作区

- 将客户概览、邮件设置、额度和密钥整理为统一设置工作区。
- 设计兼容现有调用方的全库客户搜索契约，并把搜索条件纳入可分享 URL。
- 模板编辑器改为可恢复的 URL 状态，完善保存版本、预览状态和未保存拦截。
- 创建客户路由化为“创建 → 接入清单 → 详情”的连续流程。

### 第三阶段：记录处理闭环

- 记录详情和人工结算改为路由化抽屉，保留筛选、分页和返回上下文。
- 统一待确认计数来源，首页、导航和记录页复用同一份查询结果。
- 移动端记录卡片、处理操作和冲突恢复。

## 验收标准

- 未登录直达深层 URL，登录后回到原路径、查询参数和锚点。
- 客户列表和记录列表不再一次加载全部历史；默认分页为 20。
- 刷新、短暂网络错误和局部保存失败不会清空页面控制器或已显示数据。
- 创建客户、客户详情、待确认记录可以通过 URL 恢复和分享。
- 模板未保存时，应用内导航、浏览器后退和刷新都有明确保护。
- 关键操作在桌面和手机宽度下都可完成；减少动效时仍能理解状态变化。
