执行 `docker build -t mailquota:local .` 成功。运行镜像约**90.4MiB**，不包含前端构建依赖、Python 或编译器。

执行 `node test/container-check.js` 成功。测试使用独立目录、临时管理员、隔离客户和可信临时TLS证书；SMTP模拟器运行于宿主机，不连接阿里云。生产入口 `src/server.js` 在Linux容器中运行，容器限制1CPU、256MiB内存。

| 空闲容器内存（docker stats） | 28.80MiB |

这是一分钟级短时检查，内存为docker stats采样值（非瞬时绝对峰值），响应包含本机TLS模拟SMTP，不代表真实阿里云时延，也不代表长时间运行或目标生产主机性能。

恢复演练结果：

2. 删除并重建容器，`used_count=10`保持不变。
3. 停服、保留原目录、恢复快照，配置/模板正常，`used_count=10`且原请求仍为accepted。
4. 在第11次SMTP DATA读取后强杀进程；重建后`used_count=10,reserved_count=1`，该记录为unknown，未再次发送。
5. 临时运行容器已停止并移除；测试数据仅保留在被.gitignore排除的test-output中。

- `node test/deployment-check.js`通过：真实Nginx容器`nginx -t`、Compose配置校验、备份脚本POSIX shell语法检查。使用临时证书替代真实域名证书。

- 实现参考：[Node.js版本维护](https://github.com/nodejs/Release)、[Express 5](https://expressjs.com/en/guide/migrating-5/)、[Nodemailer SMTP连接API](https://nodemailer.com/extras/smtp-connection)。
